我做了一個大學畢業專題 內容是這樣的我們重新建置了一個已經存在的生產線(那個是PLC做的) 然後我們用多塊arduino(ESP8266 wifi板)做一個IOT的東西來監控產地現在的狀態 (包括了四周的溫溼度感測器 作業環境的空氣品質 以及PM2.5等顆粒的sensor) 這是利用lan直接無線傳到我的主控PC 還有一個webcam (直接連到PC)利用yolo推算並監控危險區域有沒有人 重點是有一個現場的dashboard實時展現現在產線狀態 然後我們是用LAN來串連整個系統的 然後我們用數位雙生的技術來做在dashboard點擊 改變plc的狀態例如開始結束 以及調整參數的部分 實作部分我拆成前後端以及ui部分 後端方面是我主要負責的 架構大概是這樣一個 Spring Boot 專案結構，採分層設計；cam 放影像辨識相關 DTO 與資料模型（DetectedObjectDTO、SensorDataCam），sensor 放各類感測器資料模型（空氣品質、溫溼度、電力、PM2.5 等），plc 放 PLC 位址模型與控制器（DPoint、MPoint、PLCController），service 為業務邏輯層依設備類型拆分多個 Service（AirQuality、AirParticulates、Circuit、PLC、Cam、TemperatureAndHumidity、Data 等），每一個都有獨立的request 跟response DTO 確保資料一致性 db 資料夾放entity repository 等等映照資料庫，並由多個 分散任務性質的Controller 對外提供 API 而我還有taskprocessor jobtask物件跟queueservice實作優先級任務，DemoApplication 為啟動入口，整體為 IoT 多設備資料蒐集與整合後端架構 另外後端還採用PQ緊急程度優先演算法來控制所有請求就是非同步工作模式 我還應用多線程處理同時大量資料 我的資料庫資料表有四張表對應四個sensor類別 允許前端透過請求要求查看歷史資料 我也有全域都有log追蹤程式執行情況 也有接口允許前端查看後端log 另外我也用了.env存重要資料 後端整體運作流程大概是controller 裡面getmapping收到請求 解requestbody 塞進queue排隊 抽出來後交給service處理邏輯再透過completableFutue傳回去前端 ,sensor部分則是透過controller裡面postmapping 解requestbody後傳到queueservice排隊等被抽到service商業邏輯裡面快邏輯是存到concurrentmap裡面等待之後的要求可以馬上回傳  我還有一個scheduled是每隔一對時間掃描一次concurrentmap傳進db 還有一個看門狗scheduled定期掃描設備離線
